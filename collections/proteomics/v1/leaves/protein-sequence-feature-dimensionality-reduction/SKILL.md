# protein-sequence-feature-dimensionality-reduction

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

A deep-learning dimensionality-reduction step from EMCBOW-GPCR that feeds the concatenated 1011-D GPCR feature vector (word-embedding features WEF + bag-of-words features BF) into a small fully connected network and intercepts its 505-D Layer-1 output as the final feature representation for downstream Extreme Gradient Boosting.

## When to use

Use when a high-dimensional concatenated protein-sequence feature vector (e.g. 1011-D word-embedding + BOW features) must be compressed to a compact representation (505-D) before training a tree-based classifier such as XGBoost.

## When NOT to use

- Input is already a compact feature table (e.g. the 505-D Layer-1 output) that can be fed directly into XGBoost without further reduction
- The task is GPCR prediction from raw sequences rather than from precomputed WEF+BF feature vectors — in that case start with the CBOW/BOW feature-extraction steps instead of the reduction module

## Inputs

- Concatenated 1011-D GPCR feature vectors (word-embedding features WEF + bag-of-words features BF) with class labels from the EMCBOW-GPCR benchmark dataset
- Trained model configuration/code from https://github.com/454170054/EMCBOW-GPCR/blob/main/code/GetResults.py

## Outputs

- 505-D reduced feature matrix with one vector per sample (saved as dl_features.npy)
- Trained DL model weights (generated by running GetResults.py) reusable in Predict.py

## How to apply

Load the concatenated 1011-D F_GPCR feature vectors (WEF + BF) and class labels from the EMCBOW-GPCR benchmark dataset files. Build the DL module from the repo's GetResults.py with three fully connected layers and two Batch Normalization layers using Leaky ReLU activations, sized so that the output of Layer 1 (505-D) can be intercepted as the final features. Compile with focal loss / binary cross-entropy and the Adam optimizer with learning rate 0.01, train for a maximum of 20 epochs with batch size 32, and apply Early Stopping with a patience of 3 epochs. Run the trained network on all samples, intercept the Layer-1 output, and save the reduced feature matrix to dl_features.npy for the XGBoost classifier; per the paper, 'we intercepted the output of Layer 1 as the input features of XGBoost'.

## Related tools

- **XGBoost** (Downstream Extreme Gradient Boosting classifier that consumes the intercepted 505-D Layer-1 features) — https://github.com/454170054/EMCBOW-GPCR
- **Gensim** (Used upstream to build and train the CBOW word-embedding models whose word vectors form the features being reduced) — https://github.com/454170054/EMCBOW-GPCR/blob/main/code/GetCBOWFeatures.py

## Examples

```
python GetResults.py  # generates DL models first; then python Predict.py "test.fasta"
```

## Evaluation signals

- The saved feature matrix (dl_features.npy) contains exactly one 505-D vector per input sample, matching the paper's Layer-1 interception design
- Training respects the configured caps: maximum 20 epochs, batch size 32, Adam learning rate 0.01, Early Stopping patience of 3
- The network architecture matches the design: three fully connected layers and two Batch Normalization layers with Leaky ReLU activations
- Downstream XGBoost trained on the 505-D features attains the reported performance regime (combined features AUC ≈ 0.9423 with CatBoost as a reference point; XGBoost selected as the best-performing algorithm)
- First run regenerates the models as documented: GetResults.py is executed before Predict.py, and Predict.py accepts a FASTA file argument

## Limitations

- The DL model structure (number of layers and units per layer) is flexible and difficult to optimize; the authors note it is 'very flexible and difficult to find the best structure'
- The hyperparameter N used in Word Embedding is flexible, hard to determine the best value, and may significantly influence feature quality
- Version numbers for the software packages are only in requirements.txt (Python 3.7.0 environment required); the paper text does not state versions
