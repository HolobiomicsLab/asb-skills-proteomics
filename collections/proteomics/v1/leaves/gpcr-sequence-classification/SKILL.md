# gpcr-sequence-classification

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Classify GPCR sequences using the EMCBOW-GPCR pipeline: split sequences into segments, train CBOW word-embedding models with Gensim, extract BOW features, concatenate both feature sets, reduce dimensionality with a deep-learning model, and classify with XGBoost.

## When to use

Use when the input is GPCR amino-acid sequences (e.g., a FASTA file) that must be classified as GPCR vs. non-GPCR, or when benchmarking feature representations (BOW, CBOW word-embedding, or their concatenation) for GPCR identification.

## When NOT to use

- Input is already a numeric feature table or embedding matrix rather than raw amino-acid sequences — the sequence-segmentation and CBOW/BOW extraction steps are unnecessary.
- The task requires classifying GPCR subtypes/families rather than the binary GPCR identification that EMCBOW-GPCR performs.
- Fast retraining is required with large data and no access to a GPU-free fast classifier — note CatBoost trains much faster than other tested algorithms, but DL model structure tuning (layers/units) is difficult and may dominate runtime.

## Inputs

- GPCR sequences in FASTA format (e.g., test.fasta)
- Benchmark GPCR dataset with label file (from the EMCBOW-GPCR repository), loadable with pandas
- Pre-trained CBOW models per segment length (Ql=2, 3, 4), generated by GetResults.py on first run

## Outputs

- Binary GPCR/non-GPCR classification predictions per input sequence
- AUC, Accuracy, Mcc, and Precision metrics from 5-fold cross-validation (20 repetitions)
- Trained CBOW word-embedding models (Gensim) and concatenated BOW+CBOW feature vectors

## How to apply

Split each GPCR sequence into segments of different lengths (Ql=2, 3, 4) and train corresponding CBOW word-embedding models with Gensim, selecting the best iteration by convergence of the objective function (e.g., the 74th training for Ql=2, 100th for Ql=3, 280th for Ql=4). Input each sequence into the word-embedding models to obtain word vectors while simultaneously extracting BOW features over the split segments, then concatenate both feature sets to form the original feature vectors. Feed the concatenated vectors into a deep-learning model (Layer 1 output) to reduce dimension and extract features further, and finally train an XGBoost classifier (CatBoost is the default in GetResults.py and trains much faster). Run 5-fold cross-validation repeated 20 times on the benchmark dataset; the combined features should achieve AUC ≈ 0.9423, versus 0.9391 for CBOW-only and 0.9344 for BOW-only. Set up a Python 3.7.0 virtual environment with the packages in requirements.txt, and run GetResults.py first to generate models before prediction.

## Related tools

- **XGBoost** (Final classifier trained on DL-reduced concatenated BOW+CBOW features (selected because it had the highest Acc, Mcc and AUC)) — https://github.com/454170054/EMCBOW-GPCR

## Examples

```
python Predict.py "test.fasta"
```

## Evaluation signals

- Combined BOW+CBOW features reach mean AUC = 0.9423 under 5-fold cross-validation (20 repeats), beating CBOW-only (0.9391) and BOW-only (0.9344) within small tolerance.
- Under Yu's negative-sample segmentation (4 groups of 2495 negatives), the pipeline averages AUC 95.29, Acc 88.11, Precision 89.28 versus the 400D + PC-PseAAC + MRMD + Random Forest baseline (94.13/86.28/86.62).
- CBOW training objective function increment approaches 0 beyond the selected iteration (74 for Ql=2, 100 for Ql=3, 280 for Ql=4), confirming convergence before model selection.
- First-run invariant: running Predict.py before GetResults.py fails or gives wrong results, since GetResults.py must generate the models first.
- XGBoost's Acc, Mcc and AUC must exceed those of other tested classifiers (including CatBoost) on the same features before it is selected as the final classifier.

## Limitations

- The word-embedding hyperparameter N is flexible and hard to determine the best value, and it may significantly influence the quality of features.
- The DL model structure (number of layers and units per layer) is flexible and difficult to optimize.
- Tool version numbers (Gensim, CatBoost, XGBoost) are not stated in the paper; they must be taken from the repository's requirements.txt (Python 3.7.0 environment).
- Default CBOW model selection depends on the segment length Ql and its chosen training iteration (74/100/280); using a different iteration may change results.
